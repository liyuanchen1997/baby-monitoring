# 宝宝监控 · 设计文档

> 版本：v1.0（2026-08-15 初始版）｜对应需求文档 v1.0

## 1. 架构总览

```
┌─────────────┐   WebRTC P2P (视频+音频, DTLS/SRTP)   ┌─────────────┐
│  拍摄端       │◄────────────────────────────────────►│  观看端       │
│ 手机/PC      │                                       │ 手机/PC      │
│ getUserMedia │                                       │ 播放+对讲     │
│ 动作/哭声检测 │                                       │ 截图/录制/提醒 │
└──────┬──────┘                                       └──────┬──────┘
       │ WebSocket 信令 (wss://host/ws)                      │
       ▼                                                     ▼
┌──────────────────────────────────────────────────────────────┐
│ Node.js 服务器（HTTPS, Express + ws）                           │
│ - 房间管理（一房 2 peer，只中继 SDP/ICE，不存储）                  │
│ - activity 最新状态缓存（不做事件持久化）                         │
│ - /api/info 返回 LAN IP（供二维码生成）                          │
└──────────────────────────────────────────────────────────────┘
```

- **拍摄端恒为唯一 offerer**：观看端只应答，协议上杜绝 glare，无需 perfect negotiation
- **信令只中继不存 SDP**：服务器不解析 SDP 内容，仅按房间转发
- **检测跑在拍摄端**：传感器（摄像头+麦克风）在拍摄端，观看端可能离线，检测必须持续运行；同一媒体流被三方共享消费（`addTrack` / `AudioContext` 哭声分析 / `canvas` 动作分析），互不冲突
- **房间生命周期绑定拍摄端 WS**：拍摄端断开即删房；观看端断开仅清槽位

## 3. 信令协议（WS 消息均为 JSON `{type, ...}`）

客户端 → 服务器：

| type | 载荷 | 说明 |
|---|---|---|
| `create-room` | `code?` | 拍摄端建房；`code` 为恢复码（重连后用原码重建） |
| `join-room` | `code` | 观看端加入 |
| `offer` / `answer` | `sdp` | 拍摄端发 offer，观看端回 answer，服务器原样中继 |
| `ice` | `candidate` | trickle ICE 中继 |
| `restart-request` | — | 观看端 failed 且拍摄端无动作时请求重协商 |
| `activity` | `state, seq, ts` | 检测状态上报（迁移时发 + 非 calm 每 30s 心跳） |
| `leave` / `ping` | — | 主动退出 / 心跳（客户端每 20s） |

服务器 → 客户端：

| type | 载荷 | 说明 |
|---|---|---|
| `room-created` | `code` | 6 位数字码（冲突重生成） |
| `room-joined` | `ok, reason?` | reason: `room-full` / `room-not-found` |
| `peer-joined` | — | 通知拍摄端 → 触发其发起 offer |
| `offer` / `answer` / `ice` | 同载荷 | 两 peer 场景无需 from 字段 |
| `peer-left` | `reason` | `viewer-left` / `camera-left` |
| `activity` | 同载荷 | join/rejoin 时立即补发缓存的最新状态 |
| `activity-backlog` | `missed` | 离线期间错过的事件数 |
| `error` / `pong` | `message?` | |

服务端数据结构：

```js
rooms:  Map<code, { code, camera: ws, viewer: ws|null, activity: {state,seq,ts}, viewerSeq }>
sockets: Map<ws, { code, role: 'camera'|'viewer' }>   // 反向索引，断开清理用
```

生命周期：
- 拍摄端断开 → 删整个房间 + 通知 viewer（`camera-left`）
- 观看端断开 → 清 viewer 槽 + 通知 camera（`viewer-left`），房间保留
- 心跳：服务器 30s `ws.ping()` + isAlive 标记（手机 WiFi 睡眠半开连接防线）
- activity 缓存：`cameraSeq` 记录最新 seq；转发时记 `viewerSeq`；重连时 `viewerSeq < cameraSeq` → 发 `activity-backlog{missed}`
- 发送失败（`ws.send` 抛错）→ 立即 `terminate()` 该死连接并清理

## 4. 重连分层（三独立状态机，各自恢复）

| 层 | 监控 | 恢复动作 |
|---|---|---|
| L0 WS | `ws.onclose/onerror` | 指数退避 1s→30s；重连后拍摄端 `create-room{code}`（恢复码）、观看端 `join-room{code}`；`room-not-found` → 每 2s 重试（60s 上限），显示"等待摄像头恢复…" |
| L1 ICE | `pc.connectionState` + `iceConnectionState` | `disconnected` 5s → 拍摄端 `restartIce()`（带 iceRestart 新 offer，不重建 PC）；`failed` → 拍摄端整体重建 PC（保留 WS 与房间）；观看端 failed 5s 无新 offer → `restart-request` |
| L2 媒体冻结 | `requestVideoFrameCallback` | PC connected 但 >5s 无新帧 → 拍摄端 restartIce |

**AP 隔离检测**：WS 正常 + 有 host 候选但 ICE 卡 `failed`/`checking` → 提示"路由器可能开启 AP 隔离/客户端隔离，请关闭或换网络"。

## 5. 音视频参数

- 拍摄端 gUM：`video: { facingMode: {ideal:'environment'}, width:{ideal:1280}, height:{ideal:720}, frameRate:{ideal:24} }`；`audio: { echoCancellation:true, noiseSuppression:true, autoGainControl:true }`
- 码率：offer 建立后 `sender.getParameters()` → `encodings[0].maxBitrate = 1_500_000`（config 常量）→ `setParameters`
- 观看端：`addTransceiver('audio', { direction: 'sendrecv' })`；**对讲不重协商**：首次按键才 gUM 音频，`sender.replaceTrack(micTrack)` 按下切换、松开置 null
- ICE：`iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]`，无 TURN（局域网 host 候选直连）

## 6. 动作检测（拍摄端，纯 canvas）

1. 4fps 采样（`setInterval(250ms)`，`document.hidden` 时跳过）
2. `drawImage(video, 0, 0, 160, 120)` → 隐藏 canvas → 灰度化（160x120x4 ≈ 75KB/帧）
3. 8x6=48 网格单元差分：单元内像素差 > diffThreshold 占比 >15% → changedCell；changedCells ≥ K → 本帧"有动作"
4. **光照变化过滤**：整帧 diffRatio >60%（均匀大面积）→ 判光照事件不计入；前 3s 预热忽略
5. 迟滞：连续 N 帧进入 moving、连续 M 帧回 calm；事件冷却 30s

灵敏度三档（config.js）：低(30/4/4) 中(25/3/3) 高(18/2/2)（diffThreshold / K / N）

## 7. 哭声检测（拍摄端，Web Audio）

```
stream → MediaStreamSource → AnalyserNode(fftSize: 2048) → 每 100ms 一帧
```

每帧三特征：
1. **频带能量**：300–3000Hz 平均 dB（优先 `getFloatFrequencyData`，Safari 降级 `getByteFrequencyData`）；60s 滑动窗 p20 分位做 EMA 噪声底（窗帘/空调自动学成正常）
2. **voicedness**：`getFloatTimeDomainData` 2048 样本，100–600Hz 归一化自相关峰值 >0.35 判有声（哭声周期性发声 vs 白噪自相关平坦）
3. **持续性**：滚动 1.5–2.5s 窗口 ≥70% 帧达标且最大空隙 ≤300ms → crying（滤瞬态音）

灵敏度三档：低(24dB/2.5s) 中(18dB/2.0s) 高(12dB/1.5s)（能量阈值/达标窗口）

**对讲回声抑制**：gUM 开 echoCancellation；`talkActive` 期间 cry 阈值临时 +6dB（`suppressCryWhileTalking` 默认开）
**AudioContext 挂起**：iOS 需手势解锁 → 在"开始监控"按钮 gesture 内创建；`visibilitychange` 回前台 `ctx.resume()`

## 8. 检测状态机与提醒链路

- 状态机 `calm/moving/crying`：状态迁移时发 `activity{state,seq}`；非 calm 每 30s 心跳
- 服务器缓存最新状态 + seq；观看端 join/rejoin 立即补发；`viewerSeq < cameraSeq` → `activity-backlog{missed}`
- 观看端提醒：横幅（状态驱动，calm 或 3min 超时清除）+ 振荡器三连音（880Hz，手势内解锁 AudioContext）+ `Notification.requestPermission()`（"开启提醒"手势内）+ 标题闪烁 + Android `navigator.vibrate`

## 9. 截图与录制（观看端）

- **截图**：canvas = videoWidth/Height（判 0）→ drawImage → toBlob PNG；优先 `navigator.share({files})`（iOS 对 a.download 支持差），失败走下载
- **录制**：全平台统一 canvas 兜底路径（iOS 直录远程流黑屏 bug）——rAF 循环 drawImage 到隐藏 canvas → `canvas.captureStream(30)` + 远程 audio track → MediaRecorder；mimeType 按 isTypeSupported 选 `video/mp4;codecs=avc1.42E01E,mp4a.40.2` → `video/webm;codecs=vp8,opus` → `video/webm`；`start(1000)` timeslice（修 Chrome duration 显示 bug）

## 10. 连接保障

- Wake Lock：`navigator.wakeLock.request('screen')`；`visibilitychange` 回前台重新请求；不支持（iOS<16.4）→ 提示手动永不锁屏
- ConnectionBadge：WS + pc.connectionState 归约 5 态 + `getStats()` debug 按钮

## 11. 二维码配对

- `qrcode` 库 `toCanvas`；内容 `` `${protocol}//${lanIp}:${port}/?join=${code}` ``，lanIp 来自 `/api/info`，port 取当前页面端口（dev=5173 / prod=3443）
- HomeView 读 `?join=` 预填房间码；手动输入兜底

## 12. 双端（PC + 移动）适配

- 断点 ≥1024px：桌面横向布局（视频区 + 侧边控制栏，观看端可全屏）
- 移动端：竖屏大按钮、底部操作栏、`env(safe-area-inset-*)` 安全区
- TalkButton：同时绑定 `touchstart/touchend` 与 `mousedown/mouseup`（`preventDefault` 防滚动误触）
- PC 观看端快捷键：`S` 截图、`R` 录制、`F` 全屏、空格按住对讲
- PC 拍摄端：gUM 自动选择可用摄像头；`localhost` 是安全上下文无需证书

## 13. 已知限制与边界

- 房间码无鉴权（MVP 接受，后续可加 PIN）
- iOS 锁屏/切后台关闭摄像头采集（Web 限制）：拍摄端保持前台+插电+永不锁屏
- 哭声检测启发式，无法 100% 准确
- iOS Safari 不支持网页 Notification API
- 检测误报源：窗帘、窗外车辆、光影变化
- 离线事件仅缓存最新状态（`activity-backlog` 提示次数），不做持久化

## 14. UI 设计规范（夜灯守护 · Nightlight）

**设计概念**：宝宝监控的观看端常在黑暗卧室整夜开屏，视觉语言必须从"夜晚"出发——深夜蓝紫基底 + 婴儿房夜灯琥珀色，低光护眼；大号等宽数字（房间码）还原婴儿对讲机数字屏意象；连接状态用呼吸光环表达，像一盏稳定的夜灯。与主流蓝白监控应用形成区分。

**色彩 token**（`src/style.css` `:root`）：

| token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0B1026` 深夜蓝紫 | 全局背景 |
| `--surface` | `#171D3B` | 卡片/表面 |
| `--surface-glass` | `rgba(23,29,59,.72)` | 毛玻璃面板 |
| `--border` | `#2A3158` | 描边 |
| `--text` / `--muted` | `#E8E6F2` / `#8B90B8` | 正文 / 次级 |
| `--primary` | `#F5B85C` 夜灯琥珀 | 主操作、房间码、高亮 |
| `--ok` / `--warning` / `--danger` | `#4ADE80` / `#FBBF24` / `#FB7185` | 状态色（珊瑚红比纯红夜视友好） |

**字体**：正文系统字体栈（`--font-body`）；**数字一律等宽**（`--font-num`: ui-monospace + tabular-nums），房间码大字（56–72px、字距 0.08em、琥珀色）是界面 signature。

**组件语言**：
- 按钮：胶囊形（999px）"对讲机按键"质感；主按钮琥珀底 + 深色文字 + 琥珀辉光
- 面板：毛玻璃（backdrop-filter blur 16px + 半透明表面），观看端底部控制条、PC 端侧栏
- 状态：呼吸光环 `.halo`——连接中灰、正常绿（breathe 动画）、告警红（pulse 动画）；`prefers-reduced-motion` 时禁用动画

**布局**：移动端竖屏大按钮 + 底部毛玻璃操作栏 + `env(safe-area-inset-*)` 安全区；≥1024px PC 端视频区 + 右侧玻璃面板，观看端支持全屏。

**原则**：boldness 集中在"琥珀等宽数字 + 呼吸光环"一处，其余克制；文案用动词性主动态（"开始监控"、"加入房间"），错误提示说明原因与出路，不道歉不空洞。
