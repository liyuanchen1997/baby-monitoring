## 2. 架构速览（详见 doc/设计文档.md）

- 纯局域网 WebRTC：拍摄端恒为唯一 offerer，观看端只应答
- 检测跑在拍摄端：帧差动作检测 + Web Audio 哭声检测 → 状态机（推导式 crying > moving > calm）→ WS 信令推送观看端
- 信令服务器：房间管理（一房 2 peer）/中继/心跳/activity 缓存；房间生命周期绑定拍摄端 WS
- 关键设计：检测参数集中 `src/config.js`；状态元数据统一 `src/utils/activityMeta.mjs`；录制全平台 canvas 兜底

## 5. 环境与命令

```bash
npm run dev          # 开发（server:3443 + vite:5173，热更新）
npm run build && npm run start   # 生产（单端口 3443）
npm run cert         # 生成证书（换电脑/重装后）
npm run cert:serve   # 手机装 CA（下载服务，8080 被占自动避让）
npm run smoke        # 信令 19 断言
npm run test:audio   # 音频算法单测
npm run e2e          # 浏览器自动化（E2E_PORT=3443 跑生产模式）
```

- 本机 LAN IP：192.168.31.184（可能变化，启动时终端打印）
- 证书有效期至 2028-11（certs/ 不入库，换电脑需重新生成）
- 开发服务常驻后台时用 `pkill -f "server/index.mjs"; pkill -f vite` 停止

## 6. 工作流约定（必须遵守）

1. 分模块开发，每模块完成 → 更新文档 → 展示变更摘要 → 提交 → 停止等确认
2. 每次变更必须记录 doc/CHANGELOG.md（**注意：本次教训——UI 小改也别忘了记**）
3. 改架构/协议/参数时同步 doc/设计文档.md 与 doc/需求文档.md
4. git push 需用户明确确认（红线）
5. 新增功能后跑 smoke + test:audio + e2e 三项基线
